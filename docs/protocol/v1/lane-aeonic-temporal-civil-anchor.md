# Single-day civil anchoring

The explicitly selected profile is `aeonic.operations.temporal.civil-anchor.v1`.
The one complete capability, `Aeonic.Operations.Temporal.CivilAnchor`, requires
`anchor`. It accepts a single-day authored or derived civil date and an authored
or derived civil clock, returning the existing complete `civilDateTimeSet` value
bundle. Relative days, fractional coordinates, endpoint membership, gaps, origins
and both histories are preserved under the specified translation. One long
interval remains one piece. Timezone, WTC, leap/UTC realization, elapsed-time
authority, reduced-date broadcasting and inverse operations remain separate.

Snapshot 0.1 is the recognized immutable default. Its manifest is recognized by
exact SHA-256 bytes, with binding and suites isolated under `snapshots/0.1/` and
owning source/schema/reuse inventory captured separately. Explicit mutable next
0.2 remains available and always reports `stable_conformance_claim: false`.
Existing frozen targets and shared checker helpers are unchanged. The complete
selection has no case filters or semantic opt-outs; claiming anchoring does not
require other producer capabilities.

```sh
python3 -m pip install -r runners/requirements-aeonic-operations.txt
python3 runners/run_aeonic_temporal_civil_anchor.py --specs-root ../aeonite-specs --check
python3 runners/run_aeonic_temporal_civil_anchor.py --specs-root ../aeonite-specs --sut 'command arguments' --report anchor-report.json
python3 runners/run_aeonic_temporal_civil_anchor.py --specs-root ../aeonite-specs --manifest cts/aeonic-temporal-civil-anchor/v1/aeonic-temporal-civil-anchor-cts.v1.next.json --sut 'command arguments' --report anchor-next-report.json
```

Use the exact owning specification revision recorded in the manifest, including
its new source/schema and six unchanged frozen reuse authorities. The runner
checks source/schema/reuse/binding/suite/helper fingerprints before execution and
checks integrity again afterwards. CI and tests use `AEONIC_ANCHOR_SPECS_ROOT` so
this new pin need not replace other lanes' dependency checkouts. Python 3.9+ is
supported. Execution uses argument parsing without a shell, a process timeout and
a bounded controller read of protocol output; these are not heap or disk quotas.

## Closed logical boundary and transport

The logical request is `{operation:"anchor",input:{anchor,clock,context?,policy?}}`.
Context and policy each admit only an optional profile string. Both are validated;
policy overrides context. Selection is explicit. Results and logical configuration
are closed; diagnostics produce no value. Optional diagnostic messages are not
semantic assertions. The complete success envelope has anchoring metadata, while
its `value` remains compatible with the existing civil date-time value format.

`cts.protocol.v1` supplies lane, case identity, exactly one of `fixture.request`
or `fixture.requestText`, and trusted `policy.resourceLimits`. Outer transport
extensions are allowed, while fixture and policy objects are closed. All eleven
settings are explicitly sent. Null resource maps, unknown names, Booleans,
negative/fractional/unsafe values are harness errors. The suite has admitted
threshold and fixed denial companions for every dimension. Native host defaults
and combined support floors are not implied by the selected calibration.

Logical byte measurements preserve raw number spellings, including `-0`, unsafe
integers and extreme exponents in opaque deferred payloads. Structured logical
requests use compact JSON; text requests retain whitespace and duplicate keys.
Raw spellings are retained by artifact decoding and STDIO encoding. Diagnostics
are fixed fixture assertions, not generated by the positive mathematical oracle.

## Assertions and verification limits

The suites cover exact translation and metadata, independent admission dimensions,
seven-stage diagnostic precedence, malformed/canonical operand boundaries,
deferred categories and transport. Every operation execution checks the complete
observed response: exact output pieces, endpoint flags, histories, origins,
effective profile, or diagnostic reason/stage/pointer. Protocol status, errors and
warnings must agree. Returned human-readable messages may vary.

Snapshot 0.1 captures all 234 operation cases unchanged: 45 successful values
and 189 diagnostics. The [snapshot record](../../conformance/civil-anchor-snapshot-0.1.md)
retains genuine JavaScript, Python 3.9 and Python 3.14 executions of both frozen
and mutable targets. A stable report requires recognized frozen bytes, every
mandatory case executed and asserted in the current run, no failures, and
unchanged artifacts after execution. Modified/unknown immutable manifests,
filtered runs, missing executions and wrong responses cannot establish a claim.
The [original working record](../../conformance/civil-anchor-working.json) remains
historical harness-only evidence; its fixture replays are not provider runs.

`--check` validates artifacts and positive mathematical images without invoking a
provider; it reports `semantic_execution: false` and zero SUT executions. Harness
tests replay fixtures, deliberately corrupt returned values and every diagnostic
reason/stage/path, and include a real subprocess passing/wrong-response control.
Those controls establish assertion sensitivity and transport, not anchoring
implementation conformance. The bounded helper checks only successful fixtures;
it does not implement a staged diagnostic evaluator and cannot be the SUT.

Implementation claims require executing the entire selected target against each
real provider. Separately verify native JSON graph admission, cycle/shared-subtree
behavior, actual conversion/construction guards, host framing and selected
capacities. The JSON protocol cannot exercise native getters/proxies/subclasses
or prove a whole-chain, heap, disk or browser capacity. Checker guard observations
and large compact fixtures do not establish those native guarantees. Downstream
date-time API calls are not required of an anchoring-only provider; application
chains must explicitly select the next operation's profile and pass the complete
returned value bundle.
